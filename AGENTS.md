# Certify 2.0 — Development Instructions

## Objective
Upgrade Certify into a premium, resume-worthy credential verification and document intelligence platform.

## Development Rules
- Inspect existing code before making changes.
- Preserve working functionality.
- Follow modular and scalable architecture.
- Write clean, maintainable and reusable code.
- Explain important technical decisions in beginner-friendly language.
- Never expose API keys, passwords or environment variables.
- Never delete existing data without approval.
- Run relevant tests after every implementation.
- Do not commit, push or deploy without approval.

## Frontend Requirements
- Premium SaaS dashboard.
- Modern, minimal and professional UI.
- Dark and light mode.
- Indigo accent colors.
- Responsive layouts.
- Interactive analytics charts.
- Smooth, purposeful animations.
- Consistent typography and spacing.
- Proper loading, empty and error states.
- No unnecessary gradients or generic-looking components.

## Backend Requirements
- Modular Express architecture.
- PostgreSQL and Prisma.
- Secure authentication and authorization.
- Redis and BullMQ for background processing when introduced.
- Real-time processing updates.
- API documentation.
- Input validation and centralized error handling.

## Verification Requirements
- Evidence-based credential verification.
- Explainable risk scoring.
- OCR and structured field extraction.
- Duplicate document detection.
- Issuer verification.
- Never claim authenticity based solely on AI, OCR or keyword matching.

## Workflow
Work on one development phase at a time. Wait for approval before starting the next phase.
